# 대표 썸네일 생성

대표 썸네일은 글 제목을 그대로 그림에 적는 표지가 아니다.
작은 카드에서도 글의 핵심 구조나 문제 상황을 한눈에 구분하게 하는 시각적 단서다.

## 생성 순서

1. 본문이 확정된 뒤 제목, 한 문장 결론, 핵심 개념 2~3개만 추린다.
2. 설치된 `imagegen` 스킬을 읽고 기본 내장 이미지 생성 도구를 사용한다.
3. 글마다 한 장을 생성하고 결과를 직접 확인한다.
4. 프로젝트 밖 기본 생성 경로의 원본은 그대로 두고 최종 이미지를 글 디렉터리의 `images/`에 복사한다.
5. JPEG 품질 85 안팎으로 변환해 저장소 크기를 줄인다. 변환 도구가 없으면 PNG를 유지한다.
6. `scripts/validate_thumbnail.py <글.md>`로 앞표지, 파일, 비율을 검증한다.
7. 마크다운과 이미지를 같은 커밋에 포함한다.

## 경로 계약

파일명은 마크다운 파일명과 연결해 충돌을 피한다.

```text
<글 디렉터리>/images/<글 파일명>-thumbnail.jpg
```

마크다운 맨 위 앞표지에는 파일 기준 상대 경로를 기록한다.

```yaml
---
thumbnail: ./images/<글 파일명>-thumbnail.jpg
---
```

- 허용 확장자는 `.png`, `.jpg`, `.jpeg`, `.webp`, `.avif`다.
- 외부 URL, 저장소 루트를 벗어나는 경로, query와 fragment는 사용하지 않는다.
- 기존 앞표지가 있으면 `thumbnail`만 추가하고 다른 키를 보존한다.

## 기본 시각 방향

- 목적: 개발 블로그 글 카드용 대표 이미지
- 비율: 16:9 가로형
- 구도: 초점 하나, 큰 형태, 안전한 바깥 여백
- 색: 짙은 남색 바탕, 청록·하늘색 중심, 주제 구분용 보조색 한 가지
- 표현: 기술 개념의 흐름, 경계, 관계, 충돌을 구체적인 시각 은유로 표현한다.
- 금지: 제목 문구, 글자, 숫자, 로고, 워터마크, 코드 화면, 의미 없는 사람·두뇌 이미지

같은 시리즈는 색과 재질을 맞추되 각 글의 핵심 구조가 서로 구분되게 한다.
제목만 바꾼 비슷한 네트워크 그림을 반복하지 않는다.

## 프롬프트 구성

다음 항목을 한 프롬프트에 명시한다.

- 용도와 글 제목
- 핵심 문제를 나타내는 장면 또는 물체
- 시각 스타일과 색
- 16:9 구도와 작은 카드 기준
- 글자, 로고, 워터마크 금지

본문 전체를 프롬프트에 넣지 않는다.
공개하면 안 되는 업무 정보와 내부 식별자는 먼저 일반화한다.

## 실패 처리

이미지 생성이나 검증이 실패해도 글 작성 자체는 완료한다.
이때 `thumbnail`을 기록하지 않으며 fos-blog의 카테고리별 생성 이미지가 대신 표시된다.
빈 파일이나 존재하지 않는 경로를 앞표지에 남기지 않는다.
