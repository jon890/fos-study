# 공개 범위

업무 기록을 공개 블로그에 쓸 때 적용한다. 저장소 `CLAUDE.md`의 민감 정보 규칙이 단일 소스이며, 이 문서는 코드와 근거를 일반화하는 판단만 보충한다.

## 남길 수 있는 내용

- 공개 제품 문서에서 확인할 수 있는 기술과 오픈소스 이름
- 문제 원인, 선택한 해결 방식과 검증 결과
- 본인이 한 구현과 협업이 기술 결정에 미친 영향
- 다른 조직에서도 재사용할 수 있는 구조와 실패 사례

## 일반화하거나 제거할 내용

- 내부 URL, IP, 계정과 서비스 식별자
- 공개되지 않은 상품명, 확률과 사업 규칙
- 고객사 요구, 계약 조건과 내부 로드맵
- 회사 전용 패키지명, 클래스명과 테이블명
- 본인이 구현하지 않은 팀 전체 성과

코드 예시는 실제 구현을 확인한 뒤 공개 가능한 구조만 다시 작성한다. 비즈니스 로직 전체를 복사하지 않고 인터페이스, 상태 전이와 실패 처리처럼 글의 판단에 필요한 부분만 남긴다.

경계가 모호하면 다음 질문으로 판정한다.

- 이 이름이나 값으로 내부 시스템을 특정할 수 있는가?
- 이 코드를 공개 저장소 예제로도 사용할 수 있는가?
- 이 결정은 기술 원리인가, 공개되지 않은 사업 전략인가?

하나라도 공개 위험이 있으면 일반화하고, 일반화하면 핵심 설명이 사라지는 경우에는 해당 내용을 쓰지 않는다.
