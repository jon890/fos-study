## 팀 README

각 팀 `README.md`에는 다음 내용을 둔다.

- 회사, 팀, 기간과 기술 스택
- 팀에서 의미 있는 카테고리로 구분한 문서 목록 표
- 선택 항목인 기술 키워드 태그

문서 목록 표의 각 행에는 기간, 업무 한 줄 요약과 문서 링크를 넣는다.
링크 텍스트는 파일명이 아니라 대상 문서의 H1 제목을 사용한다.

## 업무 문서

- 진행 기간을 `**진행 기간**: 2024.06–2024.12` 형식으로 적는다.
- 회사명, 팀명과 내부 시스템 이름은 일반 표현으로 바꾼다. 팀 README의 회사와 팀 메타 정보는 그대로 둘 수 있다.
- 내부 URL과 IP는 제거하거나 `<내부-엔드포인트>`로 바꾼다.
- 운영 중인 상품과 서비스 이름은 공개하지 않고 동작과 구조를 설명하는 일반 표현으로 바꾼다.
- 새 문서를 추가하면 같은 팀 `README.md`의 문서 목록도 갱신한다.

## 업무 서사와 기술 개념

`task/`에는 업무의 배경, 막힌 지점, 내 기여, 협업과 회고를 작성한다.
기술 폴더에는 개념, 작동 원리와 일반적인 트러블슈팅을 작성한다.

업무 글에 긴 개념 설명이 필요하면 기술 폴더에 별도 문서를 만들고 연결한다.
한 업무가 기술 폴더에서 여러 문서로 정리돼 있다면 `task/` 글은 총괄과 목차 역할만 한다.

업무 문서는 필요한 항목만 골라 다음 순서로 구성한다.

1. 왜 했나
2. 막혔던 지점
3. 검증 방법
4. 내 기여와 협업
5. 회고
6. 배운 개념 링크
