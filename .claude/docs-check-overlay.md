# fos-study 문서 감사 오버레이

공용 `docs-check`를 fos-study의 공개 학습 저장소 구조에 맞게 적용한다.
일반 절차와 의미 품질 기준은 공용 스킬이 소유하며, 이 파일에는 저장소 고유 범위와 예외만 둔다.

## 검사 범위

기본 대상은 저장소의 공개 Markdown 문서다.

- 기술 학습 문서: `architecture/`, `database/`, `java/`, `devops/`, `AI/` 등 기술 카테고리
- 업무 서사: `task/<팀>/`
- 보존 예외: `resume/`
- 문서 인덱스: 각 폴더의 `README.md`
- 하네스 문서는 사용자가 스킬이나 지침 감사를 요청한 경우에만 포함

`.git/`, `node_modules/`, `.claude/`, `.codex/`, `.agents/`는 일반 학습 문서 검사에서 제외한다.

## 먼저 실행할 구조 점검

fos-study에는 별도 ADR 트리가 없으므로 공용 `static-check.sh`에 임의 경로를 넘기지 않는다.
다음 저장소 전용 점검을 먼저 실행한다.

```bash
python3 .claude/skills/docs-audit/scripts/docs_score.py --json
```

`score: 0`이 구조 점검 통과 조건이다.
`broken_link`, `orphan_doc`, `readme_missing`, `style_*`의 세부 결과를 공용 F축 구조 무결성 리포트에 합친다.

## 프로젝트 고유 의미 판정

공용 A부터 F축에 다음 경계를 추가한다.

### 회사 맥락과 일반 지식 분리

- 특정 회사, 팀, 채용 준비와 구현 경험은 `task/`의 업무 서사인지 확인한다.
- 언제 읽어도 유효한 개념 설명은 기술 폴더가 소유하고 `task/`에서는 링크만 둔다.
- 한 문서가 회사 준비와 일반 개념을 함께 처음부터 설명하면 분리 또는 허브화를 제안한다.
- `resume/`는 공개 학습 목적과 달라도 개인 이력 보관을 위해 유지한다. 명시 요청 없이 삭제·이동하지 않는다.

### AI slop과 관심사 혼합

다음 패턴은 공용 B축 과대화와 D축 중복의 근거로 사용한다.

- 출처가 있는 사실과 작성자의 설계 제안이 같은 확신도로 이어진다.
- 대칭적인 목록과 표가 논증 없이 반복된다.
- 같은 결론이 본문, 표, 점검표에서 형태만 바뀌어 반복된다.
- 서로 다른 독자 질문을 한 문서가 동시에 해결하려 해 제목과 결론이 어긋난다.
- 업무 경험 문서가 일반 개념을 길게 복제하거나 기술 문서가 개인 기여 서사를 흡수한다.

분량만으로 AI slop을 판정하지 않는다.
충분한 설명, 트레이드오프, 실패 사례와 검증 방법이 있으면 긴 학습 문서를 보존한다.

### 보존 분류

사용자가 문서 존치 여부나 품질 분류를 요청했을 때만 다음 라벨을 쓴다.

| 라벨 | 의미 |
| --- | --- |
| `keep` | 현재 역할과 근거가 분명해 유지 |
| `refresh-needed` | 주제 가치는 있으나 근거·구조 보강 필요 |
| `merge` | 다른 문서가 단일 소스가 되는 편이 나음 |
| `archive` | 현재 학습 흐름에서는 벗어나지만 이력 가치가 있음 |
| `delete-candidate` | 역할·근거·연결 가치가 모두 약해 삭제 검토 |

삭제와 이동은 라벨만으로 실행하지 않고 사용자 승인을 받는다.

## 검증 역할

- 일반 A부터 E축과 AI slop: 범용 read-only `verifier`
- 의미 있는 교차 링크 후보: `cross-link-auditor`
- orphan 결과의 연결 위치가 모호한 경우: `orphan-doc-auditor`
- README 카테고리 배치 판단이 필요한 경우: `readme-integrity-auditor`

정적 점검이 이미 확정한 개수를 다시 세기 위해 에이전트를 호출하지 않는다.
에이전트는 의미 판단과 배치 제안에만 사용하고, 수정은 메인이 승인 범위에서 수행한다.

## 완료 조건

- `docs_score.py --json`의 구조 위반이 0이거나 남긴 예외가 설명돼 있다.
- 공용 A부터 F축 결과에 사실과 추정이 구분돼 있다.
- `resume/` 보존 예외와 `task/`·기술 폴더 책임이 지켜졌다.
- 변경했다면 문체 검사와 `git diff --check`가 통과한다.
