# 슬롯 스핀 성능 최적화: Alias Method 적용

**진행 기간**: 2025.01 ~ 2025.02

---

## 배경

시뮬레이터로 100만 스핀을 돌리다 보면 속도 차이가 꽤 크게 느껴진다. 슬롯 한 종류에 1~2분이면 끝나야 할 시뮬레이션이 10분 넘게 걸리는 경우도 있었다. 직접 기여한 비중이 크지는 않지만, 병목을 파악하면서 두 가지를 정리해두고 싶어서 기록으로 남긴다.

---

## 가중치 랜덤 선택: Alias Method

기존 구현은 가중치 누적합을 순서대로 확인해 항목을 선택했다.
가중치 배열 길이에 비례하는 탐색이 릴과 스핀마다 반복되면서 시뮬레이션 비용이 커졌다.

Alias Method는 슬롯을 초기화할 때 확률 표를 한 번 만들고, 반복 경로에서는 배열 두 개만 조회한다.
전처리는 `O(n)`, 선택은 `O(1)`이다.

확률 표를 만드는 원리와 분포 검증 방법은 [Alias Method](../../algorithm/alias-method-weighted-random.md)에 따로 정리했다.

실제 코드에서는 `SlotAliasMethodMaker.of(int[] weights)`로 표를 생성하고 `AliasTable.pick()`에서 항목을 선택했다.
가중치가 바뀌지 않는 시뮬레이션 특성상 전처리 비용보다 반복 선택 비용을 줄이는 효과가 컸다.

---

## 난수 생성기와 분포 선택을 분리했다

Alias Method는 균등 난수를 가중치 분포에 맞는 결과로 바꾸는 알고리즘이다. 난수의 예측 가능성이나 보안성을 결정하지 않는다.

성능 실험용 시뮬레이터에서는 재현 가능한 seed와 병렬 실행 비용이 중요하다. 실제 게임 결과를 만드는 난수 생성기는 보안과 규제 요구를 별도로 확인해야 한다. 시뮬레이터에서 빠른 생성기를 썼다는 이유만으로 운영 경로에도 같은 선택을 적용할 수는 없다.

이 경계를 분리하고 나니 성능 비교도 명확해졌다. 같은 난수 생성기에서 선형 가중치 탐색과 Alias 표 조회만 비교해야 알고리즘 변경 효과를 측정할 수 있다.

## 배운 것

**난수 생성과 분포 선택은 다른 관심사다.** Alias Method의 성능과 난수 생성기의 보안성을 한 선택처럼 다루면 검증 기준도 섞인다.

**성능 비교에서는 바꾼 변수만 남겨야 한다.** 난수 생성기와 가중치 선택 알고리즘을 동시에 바꾸면 어느 변경이 효과를 냈는지 알 수 없다.
