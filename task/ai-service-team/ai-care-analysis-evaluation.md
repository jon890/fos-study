# AI 돌봄 분석의 실행 경계와 그래프 기반 평가

**진행 기간**: 2026.09–현재

**상태**: 현재 담당 · 진행 중

AI 돌봄 분석·평가 시스템에서 모델 실행과 결과 평가를 개발·개선하는 업무를 맡고 있다.
분석이 어디서 실패했는지 추적하고, 실행을 마친 결과가 근거와 기대 조치에 맞는지 확인하는 데 집중하고 있다.

## 현재 풀고 있는 문제와 판단 기준

모델 호출이 끝났다고 분석 결과를 바로 사용할 수 있는 것은 아니다.
응답 형식이 맞아도 필요한 근거를 찾지 못하거나 기대 조치를 빠뜨릴 수 있다.
따라서 실행 완료, 출력 형식 준수, 근거 탐색과 업무 정확도를 나누어 보고 있다.

실행 실패에는 어느 단계까지 진행했는지 남겨 재실행할 대상을 찾고, 형식 오류에는 남은 시간 안에서 고칠 기회를 제한적으로 준다.
평가에서는 통과 여부와 실제 답변 품질을 따로 확인한다.
이 구분을 바탕으로 탐색·작성 분리, 실패 식별 정보 보존과 그래프 기반 평가를 구현했고, 앞으로 반복 검증할 사례를 구체화하려고 한다.

## 탐색과 작성을 나누고 전체 시간 상한을 유지했다

탐색·작성 실행기는 두 단계를 분리하는 방식일 때 탐색 실행 뒤 같은 세션에 작성 실행을 이어 낸다.
작성에는 결과 스키마와 작성용 추론 강도를 전달하고, 탐색에 쓴 시간을 뺀 나머지만 실행 상한으로 준다.
탐색이 실패하거나 시간 예산을 모두 쓰면 작성을 시작하지 않는다.

초기 구현 뒤 검토에서 작성 요청이 제출조차 되지 못한 실패를 보완했다.
작성 실행 식별자가 없다고 앞선 탐색 기록까지 잃으면 비용과 실패 원인을 추적하기 어렵다.
따라서 미제출 실패에는 탐색의 식별 정보를 보존하고, 실제로 제출한 작성 실행이 실패한 경우에는 그 실행의 식별 정보를 유지했다.
작성용 추론 강도도 실제 작성 제출 여부에 따라 기록한다.

## 응답을 해석하지 못한 경우와 위험도 하한 미달을 구분했다

결과 해석기는 응답 파싱 결과를 검사하고, 형식 오류나 최소 위험도 제약 미달이 있으면 고침 요청을 한 번만 낸다.
고침도 남은 시간 안에서 수행하며, 시간이 부족하면 생략 사유를 남긴다.
형식을 끝내 해석하지 못하면 실패로 처리하고, 하한 보정이 필요하지만 재요청을 쓸 수 없으면 보정 사실과 경고를 남긴다.
이 보정은 결과 제약을 적용한 사실이며, 모델 판단이 의학적으로 정확하다는 증명은 아니다.

## 그래프의 기대 조치와 답변을 비교했다

그래프 탐색 평가기는 상황별 기대 조치를 그래프에서 읽고 모델 답변과 비교한다.
기대 조치 중 맞춘 것과 놓친 것, 그래프에 없는 조치, 그래프에는 있지만 해당 상황의 기대 범위 밖인 조치를 구분한다.
그래프 조회 도구를 실제로 썼는지도 함께 기록하며, 실행 기록을 알 수 없으면 미사용으로 단정하지 않고 `UNKNOWN`으로 둔다.
토큰, 도구 호출, 하위 에이전트 수와 처리 시간도 평가 결과에 남긴다.

현재 요약의 `passed`는 모든 사례의 실행 완료, 그래프 도구 사용, 그래프에 없는 조치가 없다는 조건을 본다.
재현율, 조건 기재 여부와 비권고 조치 분리는 별도 값이므로 `passed`만으로 모든 기대 조치를 정확히 답했다고 해석하면 안 된다.
특히 조건 평가는 조건 문자열이 비어 있지 않은지 확인하며, 내용의 의미적 정확성까지 판정하지 않는다.

## 다음에 검증할 것

다음 목표는 실패를 재현 가능한 사례로 나누어 같은 조건에서 반복 확인하는 것이다.
기대 조치를 빠뜨린 답변, 그래프에 없는 조치나 상황에 맞지 않는 근거를 사용한 답변, 시간 상한에 걸린 실행을 구분해 평가할 필요가 있다.
각 사례에서 실행 기록과 출력, 평가 값을 함께 비교해 재실행이 필요한 실패와 사람이 검토할 결과를 가려내려고 한다.

이는 다음 검증 방향이며, 실제 모델을 호출한 비교 평가나 품질 개선율을 확인한 성과는 아니다.
